任务 5 · 第 2 轮提示词把每条需求写成"参数名 + 期望值"

👤 我（程茗琪）的提示词
帮我写一个 Swiper 轮播配置 new Swiper("#wySw5", {...})，必须同时满足以下 4 条，一条都不能漏：1. 无缝循环（loop: true）；2. 自动翻页每 3.2 秒一张（autoplay.delay: 3200），用户手动拖动之后自动播放不能停止（disableOnInteraction: false）；3. 圆点分页器（el 用自己的 .swiper-pagination）且可以点击跳转（clickable: true）；4. 切换效果用 3D 立方体（effect: "cube"）。写完后请逐条对照说明每一行代码对应哪条要求。
🤖 AI 的回答（逐条对照） 
new Swiper("#wySw5", {
  loop: true,                    // ← 第 1 条：无缝循环
  speed: 700,
  autoplay: {                    // ← 第 2 条：3.2 秒自动翻页
    delay: 3200,
    disableOnInteraction: false, // ← 第 2 条：拖动后不停止
  },
  keyboard: { enabled: true, onlyInViewport: true },
  pagination: {
    el: "#wyPag5",
    clickable: true,             // ← 第 3 条：圆点可点跳转
  },
  effect: "cube",                // ← 第 4 条：3D 立方体
});

并提示：把这段放进页面、加上 #wySw5 演示骨架后，可以按住拖动、点圆点、观察自动翻页来逐条验证。

验证结论（页面实测）：等待 4 秒 realIndex 自己变化 = 3.2 秒自动翻页 ✓；点圆点跳到对应照片 ✓；容器出现 swiper-cube ✓；四条要求全部通过。

任务 6 · 仿写第 7 种效果 creative先看懂官方示例，再动手改参数

👤 我（程茗琪）的提示词
我看懂了官方 creative 示例的参数结构，但 transform 里的百分号（translateX: '100%'）我不确定——它是相对谁的 100%？
🤖 AI 的回答

transform 里的百分号是相对 slide 自身 的尺寸：translateX: '100%' 表示往右挪一整张照片自身的宽度，translateY 则相对照片自身高度——和轮播容器的大小无关。这也是官方示例里用 120%、-120% 让相邻照片"刚好完全滑出视野"的原因。

👤 我（程茗琪）的追问
那 rotate: '20deg' 写在第三项里，改成 20 会发生什么？
🤖 AI 的回答

第三项是 z 轴旋转角。写 rotate: 20，照片就会绕自己的中心原地旋转 20 度；rotateX / rotateY 则分别绕横轴、竖轴转，制造 3D 透视。把数值改大改小可以直接控制歪斜程度，立即生效。

落地结果：我给演示四加了第 7 个按钮「creative 电影选片墙」，上一张缩小左移转 -14 度、下一张放大右移转 8 度，做出层层叠出的景深感。

任务 7 · 双击放大交互AI 的第一版有隐患，我做了两次升级

👤 我（程茗琪）的提示词
帮我给轮播的照片加双击放大：双击后照片放大 1.9 倍，再双击还原，带过渡动画。
🤖 AI 的回答（第一版，有问题） 
// 给每一张 img 都绑一个监听器（问题方案）
document.querySelectorAll('.swiper-slide img').forEach(img => {
  img.addEventListener('dblclick', () => img.classList.toggle('cmq_zoomed'));
});
👤 我发现的问题并要求修改
任务 4 切换效果时会 destroy(true, true) 重建实例，绑在每张 img 上会不会失效？换一种绑定方式。
🤖 AI 的回答（升级为页面级事件委托） 
document.addEventListener('dblclick', function (cmq_e) {
  var cmq_img = cmq_e.target.closest('img');
  if (cmq_img && cmq_img.closest('.wy-swiper')) cmq_img.classList.toggle('cmq_zoomed');
});
// CSS：img.cmq_zoomed { transform: scale(1.9); transition: transform .4s }
答辩要点：监听器只绑在 document 上（事件委托，少绑定、多复用），两层 closest——第一层找到双击命中的照片、第二层确认它在轮播区域内。JS 只负责开关 cmq_zoomed 类，放大倍数由 CSS 的 scale(1.9) 一处集中管理，实例销毁重建后依然有效。

任务 7 · 超纲能力 keyboard + 竖版轮播用源码验证"竖向模式下按键会不会变"

👤 我（程茗琪）的提示词
给电影选片墙轮播加键盘切换功能；照片切换方向改成竖着的（上下滑动），分页圆点也换到侧面。
🤖 AI 的回答 
var wySw7b = new Swiper("#wySw7b", {
  direction: "vertical",        // 照片上下切换，圆点自动排到右侧
  keyboard: { enabled: true, onlyInViewport: true },
  effect: "creative",
  creativeEffect: { ... },      // 选片墙层叠参数保持不变
  loop: true,
  autoplay: { delay: 2600, disableOnInteraction: false },
});
// 竖向轮播必须给容器显式高度，否则会塌陷：
// .swiper-vertical { height: 290px }

并提醒：竖向模式下键盘模块只响应 ↑/↓（查看了 Swiper 源码 keyboard 模块，←/→ 只在横向方向生效），所以提示文案要从 ←/→ 改成 ↑/↓。

验证结论（浏览器实测）：容器出现 swiper-vertical 类、活动 slide 的 transform 为 translate3d(0, -290px, 0)（垂直位移一整张照片的高度）✓；圆点在轮播右缘竖排 ✓；按 ↓ realIndex 前进、按 ↑ 后退 ✓。

番外 · 排查"轮播拖不动"顺着浏览器事件流找到真凶

👤 我（程茗琪）的提示词
轮播图按住照片拖不动，松手会弹回原位，帮我找原因并修复。
🤖 AI 的排查过程与结论

在本地的 swiper-bundle.js 里检索发现：Swiper 11 只监听 pointer 事件（7 处 pointerdown，0 处 mousedown）。按住照片时浏览器会启动原生拖图，触发 pointercancel（库里 5 处监听），Swiper 立刻中断拖拽、弹回原位。

/* 修复一：禁止图片原生拖拽 */
.wy-swiper .swiper-slide img{ -webkit-user-drag: none; }
/* 修复二：拦截轮播区域内所有 dragstart 事件 */
document.querySelector('.wy-swiper').addEventListener('dragstart', e => e.preventDefault());
/* 顺手加光标提示 */ grabCursor: true
答辩要点：这个 Bug 让我理解了浏览器事件流的优先级——原生拖拽行为会"掐断"组件库的 pointer 事件链，必须显式禁用才能让组件接管全部交互。
